# สคริปต์สำหรับดูแลข้อมูลจังหวัด

สคริปต์สองตัวนี้ใช้ตอนแก้ไข `src/data/provinces/*.ts` เท่านั้น
ไม่ได้เป็นส่วนหนึ่งของแอปตอนรัน และไม่ถูกรวมเข้า build

## geofill.js — เติมพิกัดจาก OpenStreetMap

เวลาเพิ่มสถานที่ใหม่ ให้ใส่ `lat: 0, lng: 0` ไว้ก่อน แล้วรัน

```bash
node scripts/geofill.js src/data/provinces/south.ts
```

สคริปต์จะค้นชื่อสถานที่ใน Nominatim (จำกัดเฉพาะประเทศไทย) และ
**ปฏิเสธผลลัพธ์ที่อยู่ไกลจากศูนย์กลางจังหวัดเกิน 170 กม.** เพื่อกันพิกัดผิดจังหวัด
(ตอนพัฒนาเคยได้พิกัดที่ไต้หวันมาจากการค้นแบบไม่จำกัด)

ถ้าสถานที่ไหนค้นด้วยชื่อไทยไม่เจอ ให้ทำไฟล์ override แล้วส่งเป็นอาร์กิวเมนต์ที่สอง

```json
{ "หาดสมิหลา": ["Samila Beach"] }
```

```bash
node scripts/geofill.js src/data/provinces/south.ts overrides.json
```

ชื่ออังกฤษมักค้นเจอมากกว่าชื่อไทยอย่างเห็นได้ชัด

## validate-coords.js — ตรวจพิกัดทั้งชุด

```bash
node scripts/validate-coords.js src/data/provinces/*.ts
```

รายงานจุดที่อยู่ไกลจากศูนย์กลางจังหวัดผิดปกติ ตั้งระยะเองได้ด้วย `LIMIT=200`

## gen-districts.js — สร้างรายชื่ออำเภอ

```bash
node scripts/gen-districts.js <ไฟล์ชื่อจังหวัด.json> src/data/districts.ts
```

ดึงจาก thailand-geography-json (MIT) แล้วสรุปเป็น จังหวัด → รายชื่ออำเภอ
ปัจจุบันได้ครบ 77 จังหวัด / 928 อำเภอ

## fill-districts.js — เติมอำเภอให้สถานที่แนะนำ

```bash
node scripts/fill-districts.js src/data/provinces/north.ts
```

reverse geocode พิกัดของแต่ละสถานที่กับ Nominatim แล้วเติมฟิลด์ `district`
เติมเฉพาะรายการที่ยังไม่มี รันซ้ำได้ไม่ยิงซ้ำ

**ตรวจผลก่อนเขียนเสมอ** — จุดที่ติดชายแดนมักคืนชื่อเขตปกครองของประเทศ
เพื่อนบ้านมา (เช่น บ้านรักไทยเคยได้ "จังหวัดล้างเค้อ" ของเมียนมา)
สคริปต์จะทิ้งผลที่ไม่ตรงกับรายชื่ออำเภอใน `districts.ts` ของจังหวัดนั้น

## gen-metro.js — โครงข่ายรถไฟฟ้า BTS/MRT

```bash
node scripts/gen-metro.js
```

ดึงเส้นทางและสถานีจาก OpenStreetMap ผ่าน Overpass API
ปัจจุบันได้ 7 สาย / 172 สถานี

**สองเรื่องที่ต้องรู้ถ้าจะแก้สคริปต์**

1. กรองสถานีจาก **tag ของ node** ไม่ใช่ `role` ของสมาชิก relation
   หลาย relation ใส่ role ว่างไว้ — BTS สีลมมี 11 จาก 14 สถานีที่ role ว่าง
   ถ้ากรองด้วย role จะเหลือแค่ 3 สถานี
2. บาง relation **ตกสถานีไป** เช่น BTS สุขุมวิทไม่มีหมอชิต
   เติมเองผ่าน `PATCHES` ที่ต้นไฟล์ ตรวจพิกัดจาก node ใน OSM ก่อนใส่เสมอ

Overpass ติด rate limit ง่าย สคริปต์รอ 8 วินาทีระหว่างเส้นทาง
และ retry อัตโนมัติ 3 ครั้ง

## ชุดสร้างรายการสถานที่จาก OpenStreetMap

รันตามลำดับนี้เมื่ออยากอัปเดตข้อมูลใน `src/data/osm-places.ts`

```bash
node scripts/fetch-province-boundaries.js boundaries.json
node scripts/fetch-attractions.js attractions.json
node scripts/build-attractions.js attractions.json boundaries.json
node scripts/validate-osm-places.js
```

- **fetch-province-boundaries.js** — ขอบเขต 77 จังหวัดจาก OSM
  ย่อจุดเหลือความละเอียดราว 33 เมตร ได้ไฟล์ราว 12 MB
- **fetch-attractions.js** — ที่เที่ยวทั่วประเทศ ยิงทีเดียวต่อกลุ่มแท็ก
  กรองด้วยขอบเขตประเทศไทย ไม่ใช่กรอบสี่เหลี่ยม (กรอบกินเมียนมา/ลาว/กัมพูชาเข้ามา)
- **geo-provinces.js** — บอกว่าพิกัดอยู่จังหวัดไหน ด้วย ray casting ในเครื่อง
  ไม่ต้องยิง API ทีละจุด แม่นราว 97% เทียบกับ 364 จุดที่ยืนยันด้วย reverse geocode
- **build-attractions.js** — คัด แบ่งจังหวัด สลับประเภท แล้วเขียนไฟล์ข้อมูล
- **validate-osm-places.js** — ตรวจข้อมูลที่ได้ 8 ข้อ

## make-icons.js

สร้างไอคอนทั้งชุด — favicon.ico (16/32/48) และ PNG สำหรับติดตั้งเป็นแอป
(192, 512, maskable 512, apple-icon 180)

```bash
node scripts/make-icons.js
```

รูปเป็น**กระเป๋าเดินทางสีทองบนพื้นกรม มีเครื่องบินอยู่ช่องบนและรถอยู่ช่องล่าง**
วาดด้วยสมการล้วน (สี่เหลี่ยมมุมโค้ง วงกลม สามเหลี่ยม) จึงคมทุกขนาด
ไม่ต้องมีไฟล์ต้นฉบับ แก้สีหรือสัดส่วนในไฟล์แล้วรันใหม่ได้ทั้งชุด

**ลดรายละเอียดตามขนาด** — favicon 16 กับ 32 ใช้กระเป๋าเปล่า เพราะเครื่องบิน
กับรถเหลือไม่กี่พิกเซลจนเละ ส่วน 48 ขึ้นไปใส่ครบ
ตอนออกแบบให้เรนเดอร์เทียบที่ขนาดจริงก่อนเสมอ อย่าตัดสินจากรูปใหญ่อย่างเดียว

**ล้อของรถต้องยื่นพ้นตัวถังลงมา** ไม่งั้นทั้งคันรวมเป็นก้อนเดียวแล้วดูเหมือนเนินเขา
(แบบแรกที่ลองใช้สามเหลี่ยมเป็นหลังคาออกมาเป็นแบบนั้นพอดี)

`.ico` เป็นแค่กล่องใส่ PNG หลายขนาด เขียนเองได้ไม่ต้องใช้เครื่องมือแปลง


## ชุดเติมอำเภอให้ข้อมูล OpenStreetMap

`osm-places.ts` กับ `osm-restaurants.ts` รู้แค่จังหวัด ไม่รู้อำเภอ
สองสคริปต์นี้เติมให้ เพื่อให้หน้าแนะนำเที่ยวกรองตามอำเภอได้

```bash
node scripts/fetch-district-boundaries.js district-boundaries.json
node scripts/fill-osm-districts.js district-boundaries.json
node scripts/validate-osm-places.js
node scripts/validate-restaurants.js
```

- **fetch-district-boundaries.js** — ขอบเขต 931 อำเภอ (admin_level=6)
  ยิงทีละจังหวัดไม่ใช่รวดเดียว เพราะทั้งประเทศราว 170 MB เสี่ยง timeout
  ใช้เวลาราว 5 นาที ได้ไฟล์ราว 38 MB (ไฟล์ชั่วคราว ไม่ต้อง commit)
- **geo-districts.js** — หาอำเภอจากพิกัด ใช้ ray casting ตัวเดียวกับ
  `geo-provinces.js` ทั้งหมด แต่**แคบวงเหลือเฉพาะจังหวัดที่รู้อยู่แล้วก่อน**
  เร็วขึ้นมาก และวิธีสำรอง (เลือกขอบใกล้สุด) ปลอดภัยขึ้นเพราะอย่างมาก
  ก็ได้อำเภอข้างเคียงที่ถูกจังหวัด
- **fill-osm-districts.js** — เติมฟิลด์ `district` ลงไฟล์ข้อมูลทั้งสอง
  ได้ราว 99.7% ส่วนที่เหลือปล่อยว่าง ดีกว่าเดา

**ผลพลอยได้ที่สำคัญ** — ขอบเขตอำเภอละเอียดกว่าขอบเขตจังหวัดที่ใช้ตอนสร้างข้อมูล
จุดที่หาอำเภอในจังหวัดเดิมไม่เจอเลยมักแปลว่า **จังหวัดเดิมผิด** สคริปต์จึงหาใหม่
ทั้งประเทศแบบเข้มงวด (ต้องอยู่ในรูปจริง ไม่เดาด้วยระยะทาง) แล้วย้ายให้
รอบแรกย้ายไป 68 จุด เช่น

| สถานที่ | เดิม | ที่ถูก |
| --- | --- | --- |
| พระราชวังบางปะอิน | ปทุมธานี | พระนครศรีอยุธยา |
| ร้านแถวหัวหิน | เพชรบุรี | ประจวบคีรีขันธ์ |
| Salt Lake de Maeklong | สมุทรสาคร | สมุทรสงคราม |

ย้ายแล้วต้องเช็กชื่อซ้ำที่ปลายทางด้วย เพราะการตัดซ้ำตอน `build-attractions.js`
ทำไว้กับจังหวัดเดิม (เจอจริง 2 จุด — ตลาดโต้รุ่งหัวหิน กับ วัดขุนอินทประมูล)

## ชุดสร้างรายการโรงแรม/รีสอร์ต

```bash
node scripts/fetch-province-boundaries.js boundaries.json
node scripts/fetch-hotels.js hotels.json
node scripts/build-hotels.js hotels.json boundaries.json
node scripts/fetch-district-boundaries.js district-boundaries.json
node scripts/fill-osm-districts.js district-boundaries.json
node scripts/validate-hotels.js
```

วิธีเหมือนชุดร้านอาหารทุกอย่าง คัดเฉพาะที่พักที่มีร่องรอยว่ามีตัวตนจริงจัง
(มีเว็บ เบอร์โทร จำนวนดาว หรือมีคนเขียนถึงใน Wikipedia) ได้ 845 แห่ง
ใน 71 จังหวัด

**สองอย่างที่ต้องรู้ถ้าจะแก้สคริปต์**

1. **แท็ก `tourism=resort` แทบไม่มีใครใช้ในไทย** — ลองแล้วภูเก็ตกับเชียงใหม่
   ได้ 0 แห่ง ที่พักที่คนเรียกว่ารีสอร์ตถูกแท็กเป็น `hotel` แล้วใส่คำว่า
   "รีสอร์ท" ไว้ในชื่อ จึงต้องดูชื่อประกอบด้วย ไม่งั้นปุ่มกรอง "รีสอร์ต"
   จะว่างเปล่า (แก้แล้วภูเก็ตได้รีสอร์ต 12 จาก 25)
2. **มีคนแท็กเขตปกครองไว้เป็นที่พัก** — เจอ "อำเภอแก่งกระจาน" เป็น
   `tourism=hotel` จึงต้องกรองชื่อที่ขึ้นต้นด้วย อำเภอ/ตำบล/จังหวัด/เขต ออก

ไม่เก็บราคา เพราะ OSM ไม่มี และราคาที่พักเปลี่ยนตามวันจนเก็บไว้ไม่มีความหมาย
ทุกแถวจึงมีลิงก์ไป Google Maps ให้ไปดูราคาและรีวิวต่อ

## test-explore-retrieval.mts — ค้นสถานที่ให้ผู้ช่วยแนะนำเที่ยว

```bash
node --experimental-strip-types --import ./scripts/alias-hooks.mjs scripts/test-explore-retrieval.mts
```

ทดสอบ `src/lib/explore-retrieval.ts` ซึ่งเป็นตัวที่ทำให้ถามได้ลึกกว่าระดับอำเภอ
โจทย์ตั้งต้นคือสามเคสที่โครงสร้าง จังหวัด → อำเภอ ตอบไม่ได้ — **บางแสน**
(ต่ำกว่าอำเภอ) **โคราช** (ชื่อเล่น) **เขาใหญ่** (คร่อมสองจังหวัด)

**สามอย่างที่ต้องรู้ถ้าจะแก้ตัวค้นหา**

1. **ห้ามใส่คำยาวสองตัวอักษรใน `STOP_WORDS`** — ภาษาไทยเขียนติดกัน คำอย่าง
   "มา" "ขอ" "ไป" จึงอยู่กลางชื่อจริงเต็มไปหมด ตัดแล้ว "นครราชสีมา" เหลือ
   "นครราชสี" และ "ขอนแก่น" เหลือ "นแก่น" · ตัดไปก็ไม่ได้อะไรด้วย เพราะช่วง
   ที่สั้นกว่า `MIN_GRAM` จับคู่ไม่ได้อยู่แล้ว
2. **ชื่อจังหวัด/อำเภอเทียบกับคำถามดิบ ไม่ใช่คำถามที่ตัดคำแล้ว** — การตัดคำ
   ทำชื่อจริงพังได้ ("น่าน" โดน "น่า" กินจนไม่เหลือ) ชื่อเขตปกครองเป็นข้อมูล
   ที่เราแน่ใจ เทียบตรง ๆ จึงปลอดภัยกว่า แต่ต้องยาว 4 ตัวอักษรขึ้นไป
   ไม่งั้นอำเภอชื่อสั้นอย่าง "คง" กับ "พล" จะไปตรงกับคำธรรมดาในประโยค
3. **รับเฉพาะที่ตรงยาวที่สุด** — ถ้ารับที่ตรงบางส่วนด้วย ท่อนย่อยจะแย่งที่
   ของคำตอบจริง เจอของจริงตอนทดสอบ: "โคราชมี" มีช่วง "ราชม" อยู่ข้างใน
   ซึ่งไปตรงกับ "ราชมงคล" "ภูพิงคราชนิเวศน์" "ราชดำริ" ทั่วประเทศ
   ผลเลยมีเชียงใหม่ สุรินทร์ กรุงเทพ เพชรบุรี ปนมา ทั้งที่ถามถึงที่เดียว

## test-chat-store.mts — ประวัติแชทสองช่องต้องแยกกัน

```bash
node --experimental-strip-types --import ./scripts/alias-hooks.mjs scripts/test-chat-store.mts
```

เดิมที่เก็บประวัติผูกกับคีย์เดียวเป็นตัวแปรระดับโมดูล พอเคยมีผู้ช่วยสองตัว
ทั้งคู่เขียนทับประวัติกัน — ถามตัวหนึ่งแล้วประวัติของอีกตัวหายทั้งดุ้น
จึงเปลี่ยนเป็น `createChatStore(key)`

ตอนนี้ผู้ช่วยรวมเหลือตัวเดียวแล้วจึงมีที่เก็บชุดเดียว แต่ยังคงรูปแบบโรงงานไว้
เพราะเป็นสิ่งเดียวที่รับประกันว่าถ้ามีหลายชุดอีกจะไม่เขียนทับกันเงียบ ๆ

สคริปต์นี้สตับ `window.localStorage` เอง แล้ว **ลบสตับทิ้งก่อนจบ** — ถ้าปล่อยไว้
Node บนวินโดวส์จะล้มที่ libuv ตอนปิดตัวแล้วได้ exit code 127 ทั้งที่เทสต์ผ่านหมด

## test-trip-suggestions.mts — การ์ดแนะนำสำหรับทริปนี้

```bash
node --experimental-strip-types --import ./scripts/alias-hooks.mjs scripts/test-trip-suggestions.mts
```

ทดสอบ `src/lib/trip-suggestions.ts` ซึ่งรวมสี่แหล่งที่หน้าตาข้อมูลไม่เหมือนกันเลย
(ที่คัดเอง · OSM ที่เที่ยว · ร้านอาหาร · ที่พัก) ให้เป็นแถวแบบเดียวกัน
ถ้าแมปผิดจะได้หมวดผิด เวลาผิด หรือหมวดงบผิด โดยที่หน้าเว็บยังดูปกติดี

**สามอย่างที่ต้องรู้ถ้าจะแก้**

1. **กิจกรรมไม่มีลิงก์แผนที่โดยตั้งใจ** — กิจกรรมเป็นสิ่งที่ *ทำ* ไม่ใช่ที่ที่ *ไป*
   จึงไม่มีพิกัดในข้อมูล การฝืนทำลิงก์ด้วยชื่อจังหวัดจะพาผู้ใช้ไปผิดที่
   ซึ่งแย่กว่าไม่มีลิงก์ มีเทสต์คุมไว้ว่าต้องเป็น `null`
2. **ชื่อซ้ำข้ามแหล่งให้ของที่คัดเองชนะ** — ที่ที่คัดไว้เองมักมีใน OSM ด้วย
   ("หาดชะอำ" อยู่ทั้งสองที่) ของที่คัดเองมีคำอธิบาย เคล็ดลับ ค่าเข้า และเวลา
   ที่ควรเผื่อ ส่วน OSM มีแค่ชื่อกับประเภท
3. **โรงแรมกับรีสอร์ตรวมเป็น "ที่พัก" ปุ่มเดียว** ต่างจากการ์ดในแท็บแนะนำเที่ยว
   ที่แยกสองปุ่ม เพราะการ์ดนี้มีหมวดเยอะกว่า ถ้าแยกอีกจะเป็น 8 ปุ่มจนล้นบนมือถือ
   ประเภทจริงยังบอกอยู่ในบรรทัดย่อยของแต่ละแถว

## test-gemini-errors.mts — ข้อความผิดพลาดของผู้ช่วย AI

```bash
node --experimental-strip-types --import ./scripts/alias-hooks.mjs scripts/test-gemini-errors.mts
```

ทดสอบ `src/lib/gemini/errors.ts` ซึ่งเป็นสิ่งเดียวที่ผู้ใช้เห็นเวลาผู้ช่วยพัง
ถ้าชี้ผิดทางจะพาไปแก้ผิดจุด และเป็นตรรกะที่ตรวจด้วยตาไม่ออกเลย

**สองอย่างที่เจอตอนเขียนเทสต์**

1. **ห้ามโทษเน็ตของผู้ใช้** — เดิมบล็อก `catch` กลืนทุกอย่างแล้วบอกว่า
   "ตรวจการเชื่อมต่ออินเทอร์เน็ต" ทั้งที่กว่าจะมาถึงบรรทัดนั้นได้ คำขอต้อง
   วิ่งถึงเซิร์ฟเวอร์เราแล้ว เน็ตผู้ใช้จึงใช้ได้แน่ ๆ ที่ต่อไม่ติดคือขาระหว่าง
   เซิร์ฟเวอร์กับ Google ต่างหาก
2. **Google ไม่ได้ตอบเป็น JSON เสมอ** — พร็อกซีหรือหน้า 502 ตอบมาเป็น HTML
   เดิม `JSON.parse` โยนแล้วเราคืนสตริงว่าง ทิ้งเบาะแสเดียวที่มีไปเฉย ๆ
   ตอนนี้แยก try ของการอ่าน body กับการแปลง JSON ออกจากกัน

`errors.ts` แยกจาก `chat-stream.ts` เพราะไฟล์นั้น import `next/server`
ซึ่งโหลดใน Node เปล่า ๆ ไม่ได้
