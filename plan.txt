## ที่มา
สเปกต้นฉบับอยู่ในไฟล์ "วันที่2" (โฟลเดอร์เดียวกัน)
เว็บวางแผนการท่องเที่ยว: จัดกิจกรรมรายวัน + คุมงบแยกหมวด + Checklist +
Places to Visit + แนะนำเที่ยวตามจังหวัด + แผนที่และระยะทาง
ล็อกอินด้วยรหัส fixed ไม่ใช้ database, deploy บน Vercel

## ข้อกำหนดจากผู้ใช้
- แผนที่/ระยะทาง : Leaflet + OpenStreetMap + OSRM (ฟรี ไม่ต้องมี API key)
- เก็บข้อมูล     : Supabase (ตาราง trip_states) + สำรองใน localStorage
- ข้อมูลแนะนำ    : ครบทั้ง 77 จังหวัด
- การรัน         : ไม่ต้องติดตั้ง/รันอะไรเพิ่มในเครื่อง — ให้รันบน Vercel
- UI             : ภาษาไทย, ธีมกรม-ทอง (โหมดเข้ม), mobile-first

## Tech Stack (ติดตั้งครบแล้ว ไม่ต้องลงเพิ่ม)
Next.js 16.3.3 (App Router, Turbopack) + React 19 + TypeScript
Tailwind CSS v4
leaflet 1.9 + react-leaflet 5 + @types/leaflet
ฟอนต์ Noto Sans Thai ผ่าน next/font/google

## กติกาสำคัญของระบบ
===============================================================================
- ลดจำนวนวัน  -> เตือนก่อน แล้วย้ายกิจกรรมของวันที่หายไปมาไว้วันสุดท้าย
                 (ไม่ลบทิ้งเงียบ ๆ)
- ค่าใช้จ่าย   -> spent = ผลรวม activity.cost + expense.amount ของหมวดนั้น
- สถานะสี     -> เขียว = ยังไม่เกินงบ / เหลือง = ใช้ไป >= 90% / แดง = เกินงบ
                 มาจาก getBudgetStatus() ที่เดียว ห้ามเขียนเงื่อนไขสีซ้ำ
- ลำดับกิจกรรม -> เรียงตามเวลาเริ่มเสมอ (แก้ลำดับด้วยการแก้เวลา)
- dayPlans     -> ยาวเท่า dayCount เสมอ คุมด้วย fitDayPlans() ทั้งใน
                  normalizeState และ reducer ตอน setDayCount
                  ไม่งั้นวันที่เพิ่มมาจะไม่มีที่เก็บจังหวัด/วิธีเดินทาง
- จังหวัด      -> Trip.provinces เป็น array เลือกได้หลายจังหวัดต่อทริป
                 ข้อมูลรุ่นเก่าที่เก็บ destination เดี่ยวจะถูกย้ายเข้ามาให้
                 อัตโนมัติใน normalizeState
- ธีมเข้ม     -> พื้นและการ์ดเป็นกรม ตัวอักษรสว่าง ทองเป็นสีปุ่มหลัก
                 ปุ่มทองต้องใช้ text-canvas (ตัวอักษรสีกรม) ไม่ใช่ text-white
                 เพราะขาวบนทอง contrast แค่ 2.4 อ่านไม่ออก
- โหมดพิมพ์   -> @media print พลิกโทเคนกลับเป็นโทนสว่างทั้งชุด
                 ไม่งั้น PDF จะได้ตัวอักษรสีอ่อนบนพื้นขาว = มองไม่เห็น
                 และพิมพ์พื้นกรมเต็มหน้าก็เปลืองหมึก
- summary-image.ts มี PALETTE ของตัวเอง ต้องแก้ให้ตรงกับ globals.css
                 ทุกครั้งที่เปลี่ยนธีม เพราะ canvas อ่าน CSS var ไม่ได้
- Auth        -> ใช้ getUser() ไม่ใช่ getSession() ใน proxy เพราะ getUser
                 ยืนยันกับเซิร์ฟเวอร์จริง ส่วน getSession อ่านจากคุกกี้ซึ่งปลอมได้
- RLS         -> จำเป็นมาก เพราะ anon key เปิดเผยในเบราว์เซอร์
                 ความปลอดภัยอยู่ที่ policy ไม่ใช่การซ่อนคีย์
- Export PDF  -> ใช้ window.print() + @media print ไม่ต้องมีไลบรารี
                 ผู้ใช้เลือก "Save as PDF" ในหน้าต่างพิมพ์ของเบราว์เซอร์
- ระยะทาง     -> ขอจาก OSRM ก่อน ถ้าไม่สำเร็จใช้ haversine x 1.3 + แสดง badge
                 เตือนว่าเป็นค่าประมาณ ไม่ปล่อยให้หน้าแผนที่พัง

## ล็อกอิน (Supabase)
===============================================================================
อีเมล + รหัสผ่าน สมัครเองได้ที่ /signup
ต้องตั้ง env 2 ตัว: NEXT_PUBLIC_SUPABASE_URL / NEXT_PUBLIC_SUPABASE_ANON_KEY
และรัน supabase/schema.sql ใน SQL Editor ก่อนใช้งาน

ไฟล์ที่เกี่ยวข้อง
  src/proxy.ts                  ต่ออายุ session + กันหน้าที่ต้องล็อกอิน
                                (Next 16 เปลี่ยนชื่อ middleware -> proxy)
  src/lib/supabase/client.ts    client ฝั่งเบราว์เซอร์
  src/lib/supabase/server.ts    client ฝั่งเซิร์ฟเวอร์ (Server Component/Action)
  src/lib/supabase/trip-store.ts อ่าน/เขียนแผนขึ้น Supabase
  src/app/login/actions.ts      signIn / signUp / signOut
  src/app/auth/confirm/route.ts ปลายทางลิงก์ยืนยันอีเมล
  supabase/schema.sql           ตาราง + RLS policy

## Deploy บน Vercel
===============================================================================
1. git init && git add -A && git commit

   Framework Preset: Next.js  (ตรวจจับอัตโนมัติ ไม่ต้องตั้งค่าเพิ่ม)

## ข้อจำกัดที่ต้องรู้
===============================================================================
- ข้อมูลอยู่ใน localStorage ของเบราว์เซอร์เครื่องนั้น เปลี่ยนเครื่อง = ข้อมูล
  ไม่ตามไป ให้ใช้ Export/Import JSON
- ล็อกอินแบบรหัส fixed กันคนทั่วไปเข้าดูเท่านั้น ไม่เหมาะกับข้อมูลลับ
- ค่าเข้า/เวลาในข้อมูลแนะนำเป็นค่าประมาณ ควรเช็กก่อนเดินทางจริง
- OSRM/Nominatim เป็น public server มี rate limit ไม่มี SLA
- พิกัดสถานที่แนะนำดึงจาก OpenStreetMap ซึ่งบางจุดเป็นตำแหน่งของพื้นที่กว้าง
  (เช่นอุทยาน) ไม่ใช่ทางเข้าที่แน่นอน ใช้ประกอบการวางแผนได้ แต่ตอนขับจริง
  ควรเช็กกับแอปนำทางอีกครั้ง
